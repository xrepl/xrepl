## G-01 — Streaming output routing (group-leader proxy + out-of-band frames)

**Severity:** High (M1 blocker). **Home:** Arc 07, opening slice.

**The gap.** Today's stdio mode shows user-code output (`io:format`, `lfe_io`,
prints from spawned processes) because the BEAM owns the terminal — it lands
there by accident of process ancestry. The moment the Rust core owns the
terminal (the inversion's whole premise), that accident stops working: output
from evaluated code goes to the BEAM's stdout, which is now a captured child
process's pipe, not the user's screen.

**Evidence.** `grep -rn "group_leader\|group-leader" src/` → no matches. The
op set (`eval`, `clone`, `close`, `ls_sessions`, `describe`, `ping`,
`load_file`, `upload_history`) has no out-of-band output frame; the dispatch
path formats final *values* only (`xrepl-dispatcher.lfe:114,123`).

**What's needed.** Per-session group-leader proxy on the BEAM side (an
io-protocol process that captures `io_request`s from the evaluator and
anything it spawns), shipped to the client as out-of-band protocol frames —
and it must *stream*: `(progn (io:format "working...~n") (timer:sleep 5000)
'done)` printing nothing for five seconds fails the M1 parity bar. This is
the classic nREPL out-of-band-output problem; the review's M1 scope silently
assumed it solved.

**Sequencing.** Build on the cleaned evaluator boundary — after Arc 06 slice4
(L-13 + L-14), not before. Protocol-schema change: touches the `protocol/`
sibling and its TypeScript client (see caveat below).

## G-02 — Interrupt op (cancel a running eval)

**Severity:** High (M1 blocker). **Home:** Arc 07, opening slice.

**The gap.** Ctrl-C at the Rust prompt during a runaway eval has nowhere to
go: no `interrupt` op exists. Today Ctrl-C works because the BEAM owns the
terminal and the BREAK handler is the BEAM's own.

**Evidence.** `grep -rni "interrupt" src/` → no matches; the op set (above)
has no cancel verb.

**What's needed.** An `interrupt` op that kills the session's evaluator
process (the session/evaluator split means the BEAM side already survives
this cleanly — the architecture is ready; only the protocol verb is missing)
and reports a structured `interrupted` result to the client. Same sequencing
and protocol-sibling caveat as G-01.

## D-01 — Frontend event-loop shape (decide before any M1 Rust code)

> **Status (2026.06.11, later the same day):** resolved in principle — see
> *Part-2 discussion outcomes* below.

**The soft spot.** The review's `Frontend` trait ("Model A now, Model B
reachable") understates the difficulty: reedline is a blocking read loop;
ratatui Model B is an immediate-mode render loop with an event pump. A trait
abstracting both is not two implementations of one interface — it's an
event-loop inversion. If Model B is to be genuinely reachable, the core loop
likely needs to be async/message-driven from day one, with reedline wrapped
as an event source. That is an M1 design constraint, not a deferrable detail.

**Home:** a locked decision section in the Arc 07 design doc, before M1
implementation starts.

## D-02 — Term handles vs whole-term EETF for inspection (decide before M2)

**The soft spot.** EETF-in-msgpack (review §4) is right for *fidelity* but
wrong as the *inspection* mechanism: shipping `term_to_binary/1` of a 200 MB
binary or a deep ETS dump to render a collapsed one-line preview is wasted
work and an OOM hazard on both sides. The Reveal-like drill-down (review §6,
feature 1) wants a server-side term cache: eval returns a bounded preview
plus a handle; an `inspect` op pages into the term incrementally. This
changes the shape of the M2 protocol extension — the review's own warning
("don't let it slip past M2 unspecified") applies to this choice too.

**Home:** a locked decision section in the Arc 07 design doc, before the M2
protocol extension is specced.

## Cross-cutting caveat: the `protocol/` sibling is now in scope

G-01 and G-02 are protocol-schema changes (a streaming-output frame, an
`interrupt` op). The program plan declares sibling packages out of scope
"except where the `xrepl` app depends on them" — this is that exception, and
it extends to the TypeScript client (which should either gain the new
frames or negotiate them away via `describe` capabilities). Named here so
Arc 07's plan inherits it as a requirement, not a discovery.

## Part-2 discussion outcomes (2026.06.11, Duncan + Claude)

Decisions reached in the part-2 architecture discussion, recorded so they
don't live only in chat. These are *directions locked for the Arc 07 design
doc* — the design doc remains the place they get specified in full.

### Resolved

1. **D-01 resolved: message-driven event core from day one.** The core loop
   is a single event channel; the protocol client (own task), reedline
   (wrapped as an input event source), and the BEAM child monitor all feed
   it; the renderer consumes it. The `Frontend` trait is "who renders
   events," not "who owns the loop" — Model B reachability is a property of
   the event channel, not the trait signature. G-01 forces this even for
   Model A: streamed output frames arrive asynchronously and must interleave
   with prompt input. (Open sub-choice for the design doc: tokio vs
   plain-threads + mpsc. Lean tokio only if the protocol client wants it;
   a REPL front-end has ~three concurrent concerns. *Update, later the same
   day:* the lifecycle resolution (item 7) tips this to **tokio** —
   `tokio::process` gives the child monitor (`wait().await`,
   `kill_on_drop`) on the same runtime as the protocol client and the
   event channel. Three consumers, one runtime.)

2. **ExternalPrinter rejected; render policy is arm-while-editing
   buffer-and-flush.** Timeline split: while awaiting an eval reply the loop
   is *not* inside `read_line()`, so streamed output prints directly — the
   common case needs no mechanism. The buffer arms only during active
   editing (late frames from background processes), and flushes on Enter —
   at which point the input line is committed, so no save-and-redraw is
   needed. Duncan's save/redraw "shell game" is the back-pocket upgrade if
   flush-on-Enter ever feels laggy. Rationale for rejecting ExternalPrinter:
   it is feature-gated/experimental upstream, and prior experiments
   (Duncan's) show prompt-corruption hazards under resize/multi-monitor —
   the same risks that motivated the feature flag.

3. **Process topology affirmed: three modes, one contract.** The xrepl OTP
   app's whole contract is "serve `xrepl_protocol` on a socket"; the BEAM
   never knows the Rust binary exists. Mode 1 *standalone*: the Rust binary
   spawns a headless BEAM child (`-noshell`), UDS, monitors it. Mode 2
   *embedded*: a host OTP app includes xrepl in its supervision tree;
   `xrepl --attach` from any terminal. Mode 3 *attach-to-prod*: same
   gesture, distribution transport (M4). The BEAM-spawns-Rust topology
   (erlexec-style) is rejected: tty ownership (foreground process group,
   SIGWINCH, raw mode) must live with the line editor, and routing
   keystrokes through the BEAM rebuilds the stdout accident G-01 removes.

4. **Packaging direction locked: single-file self-extracting binary**
   (Burrito-style). The Rust binary embeds a per-target, ERTS-included
   rebar3 release; first run extracts to a content-hashed cache dir
   (`~/.cache/xrepl/<payload-hash>/`), then execs from cache — single
   *file*, not single *process*. Version skew self-resolves via the hash;
   stale caches are GC-able. UDS-only headless release runs
   `-start_epmd false` (no surprise epmd daemon). Build inversion: cargo is
   the outer driver (xtask/build.rs ingests the rebar3 release per target);
   payload matrix per platform is CI tedium, not design risk.

5. **Detect-or-spawn semantics.** Detection is a *handshake*, not a
   file-existence check: connect + `describe` succeeds (catches stale
   sockets and protocol-version mismatch via capability negotiation).
   Spawn race (two invocations, no server): bind-or-lock first; loser
   attaches.

6. **G-01 spec details discovered here, to fold into its slice:** every
   output frame carries `{session, eval-id, stream}` so late frames get
   visible attribution at render time (e.g. a dim `[3]│` prefix when eval
   3's output lands mid-form-5); the arming buffer needs a hard cap and a
   spill policy so a runaway printer can't balloon the client.

7. **Lifecycle ownership policy — resolved** (superseding the earlier
   open version of this item, per its own anticipation). Policy:
   *spawned-by-me dies with me*; *attach mode never kills*; a server
   already present is left alone. Server-death while attached: status
   update to the user, then two offers — "create another?" and, on yes,
   "replay your session history to recreate state?" Replay must be framed
   honestly as **re-execution, not state restoration** (side effects —
   file writes, sends, named-process starts — re-run); a teaching-quality
   touch is flagging any form whose replayed result differs from the
   recorded one (drift made visible). Convergence note: replay is the
   same mechanism the typed-REPL exploration validated (stateless
   session-replay, design note 08, 5.3 ms cold start), the protocol
   already has `upload_history`, and arc5 slice3's per-session history
   files (L-05) are exactly the substrate it reads. Three threads, one
   feature.

8. **Child-process mechanics (mode 1), resolved.** No erlexec-equivalent
   needed — the event core *is* the supervisor; the child monitor is a
   `tokio::process` `wait().await` task emitting `ChildDown`. Three
   problems solved separately:
   - *Graceful shutdown — a three-rung ladder, each rung with a timeout:*
     (1) protocol-level shutdown, (2) SIGTERM — modern ERTS translates it
     to `init:stop()`, so `terminate/2` callbacks run and slice3's
     history-save fires, (3) SIGKILL as the floor.
   - *Whole-tree kill:* the BEAM is a process tree and user code can grow
     it (`open_port`, `os:cmd`); spawn it in its own process group and
     escalate against the group (`CommandExt::process_group` + `killpg`,
     or the `process-wrap` crate for Unix-groups/Windows-Job-Objects
     behind one API).
   - *Parent-crash orphan protection:* cannot live in Rust (no cleanup
     runs on SIGKILL/panic). Inverted port-program trick: Rust holds a
     pipe as the BEAM child's stdin; a ~20-line LFE watchdog in the xrepl
     supervision tree reads stdin and calls `init:stop()` on EOF — kernel
     closes the pipe on parent death, no polling, portable.
     Belt-and-braces on Linux: `prctl(PR_SET_PDEATHSIG, SIGTERM)` via
     `pre_exec`.

### New gap minted by item 8

- **G-03 — server `shutdown` op.** The graceful ladder's rung 1 needs a
  protocol verb; the op set has `close` (per-session) but no server-level
  shutdown. Same home as G-01/G-02 (Arc 07 opening slices), same
  protocol-sibling caveat. Small.
