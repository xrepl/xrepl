## 3. State of play (2026.06.11, end of part 2)

**Settled (details in the addendum):** three-mode topology (standalone /
embedded / attach-prod; one contract: the BEAM serves the protocol and
never knows the Rust binary exists); message-driven event core on tokio;
ExternalPrinter rejected — arm-while-editing buffer-and-flush render
policy; Burrito-style single-file packaging (embedded ERTS release,
content-hashed cache extraction, `-start_epmd false`, cargo as outer
build driver); detect-or-spawn by handshake not file-check; lifecycle
(spawned-by-me dies with me via a three-rung ladder — protocol shutdown →
SIGTERM → SIGKILL-on-process-group — plus a BEAM-side stdin-EOF watchdog
for parent-crash orphan protection; attach never kills; server-death →
offer respawn + history replay, framed as re-execution not restoration).

  so any ref mutation strands `.lock` files and blocks the repo. Read-only
  git is fine. Hand Duncan the commands for anything that writes.
- File deletions need Duncan's approval (Cowork guard); he declined it for
  `.git/` internals — respect that boundary without re-asking.
- The sandbox has no usable OTP toolchain (no `erl`, install blocked).
  Anything needing a BEAM run is a host-side ask, stated plainly — grade
  unrunnable verifications as not-reproduced, never as done.
- Multiple folders are mounted; xrepl lives at `~/lab/lfe/xrepl/xrepl`
  (the OTP app) inside the `~/lab/lfe/xrepl` workspace (protocol/, term/,
  typescript-xrepl/, etc. are siblings).
