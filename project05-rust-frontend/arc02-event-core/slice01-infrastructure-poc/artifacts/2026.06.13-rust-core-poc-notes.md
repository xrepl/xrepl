## 1. What this is

A first proof-of-concept of the **infrastructure** for the inverted Rust
terminal client — explicitly *not* reading/printing/evaluating LFE. Goal: get
the plumbing (reedline + the message-driven event loop) standing, with a
zero-BEAM backend so it runs with nothing installed.

Lives in a new **Rust workspace at the xrepl org root**
(`~/lab/lfe/xrepl/Cargo.toml` + `crates/`), a sibling to `protocol/`, `term/`,
`xrepl/` (the OTP app), etc. Three members:

- `xrepl-core` — the plumbing: the event vocabulary, the tokio single-channel
  loop, the reedline input source, the `Backend` trait, the `Renderer` seam.
- `xrepl-adventure` — a tiny interactive-fiction engine implementing
  `xrepl_core::Backend`; it is *both* the mock backend and the seed of the
  in-REPL text adventure.
- `xrepl` — the binary wiring the IF engine into `xrepl_core::run`.

## 3. How the spine maps to the locked architecture

- **D-01 (message-driven core):** one `tokio::sync::mpsc` event channel; the
  reedline thread and the backend task are producers, the loop is the sole
  consumer. The `Frontend` is "who renders events," realised here as a
  `Renderer` the loop calls — not an owner of the loop.
- **AP-50 boundary:** reedline's blocking `read_line` runs on a dedicated
  `std::thread` (never a tokio worker); it bridges in via `blocking_send` (sound
  precisely because it's off-runtime) and waits on a `std::mpsc` "your turn"
  pulse from the core. This pulse-gating is Model A's request/response cadence
  on a message-driven core — which is *why* no arm-while-editing buffer is
  needed yet (that buffer is the deferred G-01 work, and the `Renderer` is where
  it will live).
- **Reachability hooks (so the deferred work needs no signature churn):**
  `#[non_exhaustive] enum Event`; every `OutputFrame` already carries
  `eval_id` + `Stream`; `XreplError` is `#[non_exhaustive]`. `CancelLine` is the
  seat reserved for G-02; a `ChildDown` variant will seat the child monitor.
- **Teardown (CA-07/CA-01):** drop the command + pulse senders to unblock the
  peers, then `await` the backend task and `join` the input thread so the
  terminal is restored. The join can't hang: at every loop-exit the input
  thread is either already exiting (EOF/error) or parked on the pulse (quit
  verb), never mid-`read_line`.
