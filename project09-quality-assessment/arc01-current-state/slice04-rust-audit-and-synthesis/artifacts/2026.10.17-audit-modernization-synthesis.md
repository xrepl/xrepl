## What needs attention first

Protect the long-lived interactive core: result attribution, bounded evaluator
stack, acknowledged close/save, expiry ownership and Rust peer-failure teardown.
Then repair real input/text/protocol boundaries and security/history controls.
Add tests at those boundaries in the same future changes; extending the current
substitute tests alone would miss the demonstrated failures. The existing shell
seam, explicit save roundtrip, pure story engine, bounded Rust queues and small
crate DAG are useful foundations to preserve.

There is no evidence-driven reason here to replace languages, upgrade the Rust
edition or redesign shared distributed infrastructure. The current Rust PoC is
already edition2024; its declared1.85 MSRV remains untested. BEAM transport,
streaming and interrupts were explicitly deferred in its selected PoC scope.
A local session-process snapshot is useful, but is not whole-VM durability.

## Recurring causes and consolidation opportunities

**Completion needs an owner.** LFE-001/003/004/016 and RUST-001/002 show different
failures of request/lifecycle completion. Resolve each language's local ownership
first: a request must retain its caller, a lifecycle transition must acknowledge
its durable-in-scope result, and a failed peer must release or terminate the
remaining work. TOOLS-001/002 repeat the error-observability problem in developer
commands. This shared diagnosis does not imply one shared runtime implementation.

**Boundary types need one meaning.** LFE-006/007/008/009/013/014/015/019 show bytes,
codepoints, parsed forms, success tuples and protocol variants interpreted
differently by adjacent modules. Keep a documented conversion/validation point
for each boundary. Preserve the raw-input need of non-LFE shells and existing
LFE parsing semantics; do not coerce everything into one string representation.
Correlating session evaluator messages and demultiplexing wire replies are
separate obligations even if both use IDs.

**Policy declarations need consumers.** LFE-010/016/017/020 expose options whose
values do not reach the enforcing layer. Consolidate configuration ownership
and explicit transport/history policy, with compatibility decisions for changed
public behavior. Secure RNG and constant-time comparison are already present;
those clean checks do not establish frame bounds, directory security or token
lifetime policy.

**Consolidation should follow a supported-call map.** LFE-021 identifies useful
live fork command helpers alongside an alternate exported shell engine and
unused ordinary-path output adapters. Document supported exports/callers before
extracting helpers or routing output through one implementation. LFE-005/006
support consolidating repeated process-name and text conversion helpers after
their contracts are fixed. Do not delete the whole fork or replace exported
APIs just because first-party call searches find no caller.

**Tests need the real seam.** LFE-018 and RUST-003 show why existing green counts
coexist with these bugs. Keep the useful pure tests and positive controls; add
neutral session/reader/dispatcher/render/core-lifecycle tests. Explicitly select
fixtures, disable unwanted history/network and test archive absence in a truly
absent fixture. Never let an optional successful real-archive branch satisfy an
absent-archive oracle. Static failures must remain visible rather than disabling
checks to produce green CI.

## Proposed sequencing and ownership

The groups below are ordered work candidates. IDs are stable; every one of the
27 findings has exactly one primary backlog row. Severity remains in the reports;
priority also considers dependencies and containment. All rows are **recommended,
unimplemented**, with follow-up planner assignment required. None closes a
historical remediation gate. Owner labels name roles to assign, not contributors
already commissioned.

Compatibility classes: **local refactor** preserves the supported contract;
**compatibility layer required** bridges a public API/storage/protocol change;
**explicit behavior change** requires a recorded product/maintainer decision.
Tests accompany each future repair. No project indices or implementation prompts
are reserved by this assessment.

## Defer and do not change on this evidence

Keep the workstation's common distributed REPL architecture discussion separate.
Do not choose shared storage/middleware, adopt a new protocol, implement Rust
BEAM/streaming/interrupt, resolve D-02 large-value representation or add typed/
GUI/IDE/distribution milestones from this audit alone. Those are prospective,
deferred or open-decision families in the map, not newly discovered defects.

Do not optimize ETS/store scans from static suspicion alone, delete the entire
fork, replace crypto, migrate editions, upgrade dependencies or run a formatting
sweep mixed with behavior changes. No third-party vulnerability audit, full
protocol/term/editor audit, real authentication or graphics/load campaign was
performed. Re-entry needs the bounded contract and evidence described above.
