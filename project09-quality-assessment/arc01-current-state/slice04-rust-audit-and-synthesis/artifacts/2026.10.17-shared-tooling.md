## TOOLS-001 — Medium — Push failures are reported as success

Location: `mk/rust.mk:183–190`. Scale: release-support task.
The loop runs `git push ... && git push ... --tags`, then unconditionally prints
success. That echo supplies the final zero status, masking a failed push and
making the Make target succeed. Contributors can believe a commit was published
when no remote accepted it.

A neutral isolated PATH stub made every git invocation fail with 42. The real
unchanged `make push GIT_REMOTES=neutral GIT_BRANCH=main` still printed `Pushed`
and returned 0. No real Git push or network action ran. Preserve the first failure
or aggregate per-remote statuses, print success only after both pushes succeed,
and add a failure-injected target check plus a successful-control check in a
separately authorized tooling fix. The observation is reproduced by Sofie's
own harness; human acceptance remains pending.

## TOOLS-002 — Medium — Dependency-check failure becomes “up to date”

Location: `mk/rust.mk:142–150`. Scale: developer-validation task.
The recipe captures cargo-outdated stdout and discards its exit status/stderr.
An error with empty stdout follows the no-updates branch and exits0. That makes
an unavailable or failed check indistinguishable from a successful check.

An isolated failing cargo stub returned 42; neutral cargo-binstall/cargo-outdated
presence stubs prevented all auto-install branches. The unchanged `make
check-deps` returned 0 and printed `All dependencies up to date`. No installer,
dependency update or network call ran. Check the cargo command's exit before
parsing output, preserve actionable stderr and distinguish error/no-updates/
updates-present. A future regression must inject an empty-output failure, not
only a known update table.
