## 3. Standing rules (hard-won this session — do not relearn these)

1. **NO git write operations from the sandbox. Ever.** The mount can create
   but not unlink files in `.git`, so any lock-taking git command strands
   lock files that block Duncan's own git (even plain `git status` strands
   `index.lock`). Safe reads: `git log`, `git show`, `git branch --list`,
   `git diff <sha> <sha> --no-optional-locks`. All mutations: hand Duncan
   the exact commands. (Memory: `sandbox-git-write-hazard`.)
2. **Naming: `arc<N>/slice<M>-<slug>`** for branches; docs are
   `arc<N>-<arc-slug>/slice<M>/`. Every scale self-labeled and grouped;
   numbering restarts per parent (Duncan's book-style model). Never pack
   two scales into one dotted token; **never rebase/renumber history** —
   evidence SHAs in closed ledgers must stay valid.
3. **Red test committed BEFORE the fix** (slice1 finding CDC-3). The red
   run must be reproducible from a plain checkout. Red-on-baseline output
   is required ledger evidence; a green-only trail is the vacuous-test
   failure mode.
4. **Ledger discipline is literal:** every row reaches done/deferred/no-op
   with command output + SHA; CDC re-runs every Verify; CC's `done` is
   proposed-done until reproduced; five iterations per slice, CDC
   rejections count.
5. **The sandbox has no BEAM toolchain** (no root, distro OTP too old, hex
   builds allowlist-blocked). CDC does statics (greps via `git show`,
   source reads, diff scope) + forensics in the sandbox; dynamic runs are
   operator-executed on the host. Write Duncan a self-contained script +
   RUNME; he chmods and runs.
6. **Verification harnesses need guards, and their verdicts are not
   evidence.** Slice 1's harness took 4 defects: (a) fresh-worktree dep
   ordering (`rebar3_lfe` compiles LFE tests before ltest is built — seed
   `_build` from a copy); (b) seeded `_build` contamination (post-fix beams
   / `lib/<app>` symlinks back to the live tree — EVICT the app from the
   copy: `rm -rf _build/*/lib/xrepl`); (c) always guard: pre-check the bug
   is present in worktree source, post-check the built beam differs from
   the repo's (`cmp`); (d) **ltest output is ANSI-colored** — greps on
   `Passed: 41` fail; read the captured log directly, never trust the
   script's verdict over the log.
7. **Forensic evidence cross-checking works** when you can't re-execute:
   check reported failure values against non-obvious artifacts of the code
   path (slice 1: the keepalive's id was `#"unknown"` due to an
   atom-vs-binary map-key mismatch; CC's red output reproduced it —
   fabricated output wouldn't).
8. **Watch for `funcall` vs `call` on module atoms** (slice1 F-6/CDC-7:
   `(funcall transport …)` where transport is a module atom = `badfun`
   crash). Grep new/touched LFE for `funcall` against module-atom vars.
9. **Known-deferred, do not fix in Arc 05:** the atom-vs-binary map-key
   family (e.g. `send-response` id lookup; the decode-error path's
   `#m(id (binary "unknown"))` literal-list value) → Arc 06
   protocol/boundary work. The keepalive test's 31 s pause is intentional;
   renaming it is deferred until someone complains. No xref/dialyzer
   re-enable (Arc 06, L-07). No `(export all)`, tag messages, etc. per the
   style guide.
10. **CC instances misnumber things and write evidence honestly when asked**
    — slice1's CC self-reported a failed paren attempt. Receive crash
    reports cheaply ("thanks, what's the actual answer"); that's the
    framework's failure-recovery protocol and it is working.
