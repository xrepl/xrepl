## Architecture-doc discovery

The repo is unusually rich in design docs (`docs/design/`, ~20 files). The
README is current and accurate to v0.2.0. The most load-bearing design docs for
this audit were `xrepl-unified-spec.md`, `distributed-repl-architecture-guide.md`,
and `xrepl-protocol-extraction.md`. **No stale-pointer problem** — the docs
describe the intended design and the code largely matches Phases 1–3. One gap:
the app advertises security controls (`require_auth`, `rate_limit`,
`max_connections`) that the design docs promise but the code never wires
(Finding L-06). That divergence between doc-as-spec and code-as-built is itself a
finding.

## The headline clusters

1. **The network/protocol layer — the exact foundation the Rust-core plan will
   build on — is the least-tested and carries every High-severity correctness
   bug** (idle keepalive desync L-01; unbounded `packet`-4 intake L-02; unbounded
   atom minting via `clone` L-03; orphaned session processes + ETS leak on
   timeout L-04; shared history-file clobber L-05). These are not style nits;
   they ship misbehaviour to a user who runs `--server` or `--hybrid`.

2. **The advertised security controls are partly decorative** (L-06): `rate_limit`
   and `max_connections` are declared in `xrepl.app.src` and never read; this is
   the kind of gap that reads as "protected" on the tin and isn't.

3. **The static-analysis safety net is down** (L-07): xref and dialyzer are
   commented out in both `rebar.config` and CI, and `min_coverage=0`. For a
   codebase that is ~50% AI-assisted LFE, the anti-pattern net is exactly what
   you want running in CI.

4. **A large vestigial surface** (M-cluster): `lfe_xrepl.erl` is a 1182-line copy
   of the LFE shell of which only the command functions and the banner are live;
   `xrepl-output.lfe`, `xrepl-transport.lfe`, and `xrepl-transport-stdio.lfe`
   appear unused by the live dispatch path. This is the cruft to clear *before*
   re-platforming onto a Rust core, not after.

## Cross-cutting

- **L-02 (unbounded intake) and L-03 (atom minting) are pre-/post-auth DoS holes
  on the same TCP path** and should be fixed together when the transport is
  touched. If the Rust REPL core takes over the socket (the architecture doc's
  direction), L-01/L-02 move to Rust and change shape — see the architecture
  review for which bugs the re-platform deletes versus inherits.
- The session-id → atom conversion (L-03) recurs in three modules
  (`xrepl-session`, `xrepl-store`, `xrepl-history`); it is one root cause with
  three call sites.
