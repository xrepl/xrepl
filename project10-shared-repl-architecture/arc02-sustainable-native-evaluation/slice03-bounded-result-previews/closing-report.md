## Structural renderer review

`attempt` dispatches empty list before the bounded string probe, empty tuple/map
before structural depth and bounded scalar APIs before compound traversal. Short
lists inspect≤256 heads and one tail; short binaries decode only≤256 bytes. Long
printable inputs become structural representations, not full scans. Lists retain
cons tails; tuples use element/index metadata; maps use only default iterator/next;
bitstrings use byte patterns and a bounded final bit-tail scalar. Siblings iterate
with a reverse accumulator, while structural descent is depth-limited.

Each compound reserves prefix/closer and marker capacity; each sibling reserves
its separator plus any remainder marker. Improper tails reserve the larger dotted
separator; map pairs reserve space plus value marker before attempting the key.
Insufficient capacity returns no_fit before subtraction. Whole omitted remainders
set true; exact small final scalar children may consume1/2 bytes. Conservative
4095-list omission is intentional, as resolved before issue; maximal utilization
is not promised. Small strings/functions/identities follow the documented policy,
not an arbitrary-term pretty printer or lossless codec.

Integer comparison against bounded `1 bsl (4*remaining)` precedes decimal conversion
and never takes a huge input abs. Only the bounded magnitude is converted, then
exact bytes are checked. At root the threshold has32769 significant bits and the
bounded decimal temporary is≤16385 bytes. Atoms/floats/PID/port/ref/function metadata
use the inspected scalar APIs; no function env is inspected. No full collection
conversion/sort/list length/fullbinary Unicode scan or whole-term printer appears.
UTF-8 fragments/ASCII form bounded iodata; final assembly returns owned bounded
text without retaining an input sub-binary. Tests alone do not establish formal
arbitrary-term complexity, elapsed-time performance, evaluation or user heap bounds.
